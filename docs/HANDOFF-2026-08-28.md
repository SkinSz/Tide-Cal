2. WORK COMPLETED THIS SESSION (fixes + discoveries)
════════════════════════════════════════════════════════════════════

2.1 Async RPC Promise-serialization bug (CRITICAL, fixed + regression test)
    handleLine() embedded the dispatcher's raw return value in the JSON
    envelope. Async ops return Promises; JSON.stringify(Promise) === {}.
    Every async op silently returned {"ok":true,"result":{}} — no error,
    anywhere. Symptom: pairing code textarea showed literal "undefined".
    Demonstration: JSON.stringify({result: Promise.resolve({qr_text:'X'})})
    === '{"result":{}}'. Fix: handleLine is async, awaits the result;
    rejections still map to ok:false. Fail-first regression test:
    tests/pairing_stdio.test.ts.

2.2 Frontend invoke-path fix (CRITICAL, fixed)
    syncOp() detected Tauri via legacy globals that don't exist in Tauri 2
    → every sync-op surface (badge, dialog, paired devices) threw
    internally and showed 0/empty in the desktop app while unit tests
    (which stub the layer) stayed green. Fix: use @tauri-apps/api/core
    invoke + __TAURI_INTERNALS__ presence check.

2.3 Zombie sidecar / port 47471 (ROOT CAUSE DEMONSTRATED; crash FIXED;
    lifecycle NOT fully solved — see §6)
    Chain: a sidecar from a previous GUI session outlives the GUI
    (systemd-user-parented orphan) and HOLDS port 47471 (the default sync
    port). The next session's sidecar starts; the first RPC that calls
    ensureListener() triggers serveSync() → EADDRINUSE rejection → the
    fire-and-forget `void serveSync(...).then(...)` chain had NO catch →
    unhandledRejection → Node exits code 1 (strict default since v15).
    Every subsequent RPC: "sidecar exited: exit status: 1".
    Demonstrated by: dummy listener occupying 47471 → spawn real bundle →
    device_info answers → STDERR EADDRINUSE → exit 1. A/B: adding .catch
    keeps the process alive. Reproduction command preserved in
    tests/ensure_listener_port.test.ts (the test IS the repro, fail-first).

2.4 ensureListener() rejection-handling fix — see §1.2 sidecar_server.ts
    entry (b). Logs, leaves host null, retries on next ensureListener().

2.5 Occupied-port regression tests — see §1.2 test entries. CRITICAL
    gotcha for anyone editing them: strip the VITEST env var from the
    spawned child or the sidecar's main() gate skips startup entirely
    (silent exit 0, no output).

2.6 GUI fixes from the owner's smoke test (all in §1.2): month-view
    dblclick regression, single-click-opens regression (chip wiring),
    Paired-button removal (merged into Devices & Sync), listening-port
    line hidden, native popup chrome eliminated, month/week click UX
    contract enforced with DOM tests.

2.7 Key discoveries about the runtime that tests did NOT cover:
